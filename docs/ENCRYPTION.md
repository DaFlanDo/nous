# Шифрование данных

Личные записи хранятся в MongoDB в зашифрованном виде. Это шифрование **на стороне
сервера** (encryption at rest), а не сквозное: сервер держит ключ и расшифровывает
данные, когда отдаёт их владельцу или передаёт ИИ. Цель — чтобы утечка дампа базы
не раскрывала содержимое записей.

## Что шифруется

| Коллекция | Поля |
|---|---|
| `notes` | `title`, `content` |
| `templates` | `name`, `items[]` |
| `checklists` | `items[].text` |
| `chat_sessions` | `title`, `messages[].content`, `history_summary` |
| `states` | `analysis` |

Идентификаторы, даты и `user_id` не шифруются — по ним идут запросы.

## Как устроено

- Шифр — [Fernet](https://cryptography.io/en/latest/fernet/) из библиотеки `cryptography`:
  AES-128-CBC + HMAC-SHA256, у каждого шифротекста свой случайный IV.
- Ключ Fernet выводится из `ENCRYPTION_KEY` через PBKDF2-HMAC-SHA256, 100 000 итераций.
- Код: `backend/app/services/encryption.py`, помощники `encrypt_note()` / `decrypt_note()`
  и аналогичные для остальных коллекций.

Без `ENCRYPTION_KEY` (или с шаблонным значением) backend не запускается.
Сгенерировать ключ: `openssl rand -hex 32`.

## Ограничения

- **Ключ один на всё приложение.** Кто получил `ENCRYPTION_KEY` и базу — читает всё.
- **Сервер видит открытый текст** во время обработки запроса, и ИИ-провайдер получает
  текст записей, когда пользователь общается с ассистентом.
- **Поиск по тексту** возможен только после расшифровки, поэтому ИИ ищет по последним
  500 записям пользователя, а не через индекс базы.
- **Смена ключа** сейчас не поддерживается: записи, зашифрованные старым ключом,
  перестанут читаться. Сбой расшифровки нашего шифротекста пишется в лог.
- Записи, сохранённые до включения шифрования, читаются как есть.
